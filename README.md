# 전투 시뮬레이터 v.0.0.1

This is a code bundle for RPG GAME 시뮬레이터. The original project is available at https://www.figma.com/design/Wq0XUFk0HnRHesPYfsRKou/RPG-GAME-%EC%8B%9C%EB%AE%AC%EB%A0%88%EC%9D%B4%ED%84%B0.

## Running the code

Node.js 22.5 or later is required (`node:sqlite` is used by the local API).

```sh
npm install
npm run dev
```

Open `http://localhost:3000`. On first launch, create the administrator account.
Administrators issue user accounts from the sidebar; each account's simulator
workspace is saved separately in SQLite. The default database path is
`%USERPROFILE%\.battle-simulator\battle-simulator.sqlite`. Set
`BATTLE_SIMULATOR_DATA_DIR` to use another directory.
User names are 3–32 letters, numbers, dots, underscores, or hyphens; passwords
must be at least 12 characters.

Run `npm test` for the frontend and API tests. For production, run `npm run build`
and then `npm start`; the API serves the built app on `http://127.0.0.1:3001`.

## 계정 복구와 DB 백업

- 일반 사용자의 비밀번호는 관리자로 로그인한 후 **사용자 계정 관리**에서 재설정합니다.
  해당 사용자의 기존 로그인 세션은 만료되며 작업공간은 유지됩니다.
- 관리자 비밀번호를 잊었다면 서버 PC의 대화형 터미널에서 다음을 실행합니다.
  비밀번호는 화면에 표시되지 않으며 12~128자로 두 번 입력합니다. 명령줄에
  비밀번호를 직접 입력하지 마세요. 이 방법은 해당 PC의 OS 계정 접근 권한에 의존합니다.

  ```powershell
  npm run reset-admin -- 관리자사용자이름
  ```

- DB 백업·복구 전에는 앱 서버와 DB를 사용하는 다른 프로그램을 모두 종료하세요.
  아래 명령은 서버 포트가 사용 중이면 거부하지만, 다른 DB 접근까지 감지하지는
  못합니다. `BATTLE_SIMULATOR_DATA_DIR`을 사용하는 경우 서버와 동일하게 설정하세요.

  ```powershell
  npm run db-recovery -- backup "C:\backup\battle-simulator.sqlite"
  npm run db-recovery -- restore "C:\backup\battle-simulator.sqlite"
  ```

  백업 폴더는 미리 만들어야 하며 기존 파일은 덮어쓰지 않습니다. 백업에는 **모든
  사용자의 계정·작업공간과 세션 정보**가 포함되므로 접근이 제한된 곳에 보관하세요.
  복구는 현재의 모든 계정과 작업공간을 백업 시점으로 교체합니다. 먼저 현재 DB를
  별도 경로에 백업하고, 복구 확인 시 `RESTORE`를 입력하세요. 복구 후 모든 사용자는
  다시 로그인해야 합니다. 현재 버전과 스키마가 다른 백업은 거부합니다.

## 작업공간 저장

변경 사항은 자동 저장되며 사이드바에서 저장 상태를 확인할 수 있습니다. 저장 오류가
나면 `다시 저장`을 누르세요. 로그아웃은 앞선 저장을 마친 뒤 현재 상태를 저장합니다.
브라우저를 닫거나 새로고침하기 전에 `작업공간 저장됨`을 확인하세요.
같은 계정의 다른 탭이나 기기에서 먼저 저장한 경우 현재 저장은 거부됩니다. 사이드바에서
서버의 최신 작업공간을 불러오거나 현재 변경 사항으로 명시적으로 덮어쓸 수 있습니다.
덮어쓰기는 상대 기기의 변경 사항을 대체하므로 내용을 확인한 뒤 선택하세요.

저장된 작업공간의 구조 오류가 발견되면 시뮬레이터를 열지 않고 오류 위치와 복구 선택지를
표시합니다. 먼저 현재 스냅샷을 JSON 파일로 내보내 보관한 뒤, 확인을 거쳐 해당 계정의
작업공간을 기본값으로 교체할 수 있습니다. 서버도 같은 구조 검사로 잘못된 저장 요청을
거부합니다. 키 바인딩, 레벨 증가식과 기본 능력치, 캐릭터 능력치 범위 및 캐릭터·몬스터
타입의 핵심 필드를 확인하며, 스킬이 내장하거나 사용자 지정 목록에 저장된 이펙트
프리셋의 필수 필드와 선택형 숫자·열거형, 아이템 슬롯과 중첩 아이템의 필드 형식도
검증합니다. 스킬·스킬 슬롯·기본 공격의 필드 구조와 캐릭터·몬스터 타입의 AI 패턴,
몬스터 행에 저장된 AI 패턴 JSON의 중첩 구조도 검사합니다. HP/SP와 몬스터 전투 능력치,
ID가 지정된 플레이어 레벨 행의 숫자 필드도 검사하며, 미완성 행과 ID 없는 레거시 플레이어
행은 허용합니다. 그 밖의 데이터 행 내부 필드와 전체 ID 참조 관계 검증은 아직 완료되지
않았습니다. 작업공간 저장은 몬스터 정의 ID가 없거나 중복된 경우, 웨이브가 존재하지 않는
몬스터 ID를 참조하는 경우, 데이터 행·캐릭터 설정·몬스터 타입의 알 수 없는 스킬 또는
캐릭터 타입 ID 참조를 거부합니다. 선택형 참조의 빈 값과 AI 패턴의 레거시 `skill1`~`skill4`
표기는 허용합니다.
웨이브에서 참조하는 몬스터 행은 삭제할 수 없습니다. 안내된 스테이지와 웨이브에서
매핑을 먼저 해제하세요. 수량이 0인 매핑도 참조로 취급합니다.
Excel의 몬스터 데이터 행에는 `monster_definition_id`가 필요합니다. 이전 파일을 이관할 때는
각 행에 고유하고 유지할 ID를 입력하고, 웨이브 매핑의 ID도 함께 갱신한 뒤 가져오세요.
기존 작업공간의 ID는 자동으로 변경하지 않습니다.
데이터를 임의로 초기화하지 말고 필요한 경우 위의 DB
복구 절차를 확인하세요. DB 복구는 모든 사용자의 데이터를 교체합니다.

## 이펙트 생성 코드

그래픽 연출 효과 화면의 템플릿에서 이펙트를 선택하면 생성 코드를 확인할 수 있습니다.
`코드 생성` 후 직접 수정하면 유효한 코드가 미리보기에 반영됩니다. `코드 삭제`는
사용자 코드만 지우고 내장 생성 방식으로 되돌립니다. 기본 프리셋의 변경 사항을
보관하려면 `저장`으로 커스텀 프리셋을 만드세요. 로그인한 사용자의 SQLite 작업공간에
다른 시뮬레이터 설정과 함께 자동 저장됩니다. 첫 관리자 계정 설정 시 기존 브라우저의
커스텀 프리셋이 있으면 작업공간으로 이전합니다.

코드 편집은 파티클 **생성**에 적용되며, 공통 업데이트·렌더링 및 레거시 이펙트
로직 자체를 편집하지는 않습니다. 코드는 샌드박스 없이 브라우저에서 실행되므로
신뢰할 수 있는 코드만 사용하세요.

Excel 내보내기는 스킬에 포함된 이펙트 목록과 생성 코드를 보존합니다. 사용자
작업공간 전체 백업은 아니며, 별도 커스텀 프리셋 목록, 전역 키 바인딩 및 스킬
슬롯 배치는 Excel 파일에 포함되지 않습니다. 가져오기 시 스킬 슬롯은 선택된
플레이어 데이터 행을 기준으로 다시 구성됩니다.
내보내기 중 JSON 데이터에 비유한 숫자가 있거나 변환에 실패하면 오류 위치를
안내하고 파일을 생성하지 않습니다. 일반 셀의 비유한 숫자와 Excel에 보존할 수
없는 객체·배열 등의 값도 시트, 행, 필드를 안내하고 내보내기를 중단합니다.
플레이어·몬스터 기본 공격 시트는 스킬 ID, 키 설정과 선택적 개별 수치를 보존합니다.
예전 파일에 해당 수치 열이 없으면 기존처럼 미설정으로 가져오고, 키 설정이 없으면
`click`을 사용합니다. 가져온 직후 선택 행의 기본 공격 설정이 있으면 그 값이 우선합니다.
Excel 가져오기는 JSON 문법 오류와 스킬·캐릭터 타입·몬스터 타입의 빈 ID 또는
중복 ID, 잘못된 숫자와 음수 스킬 SP 소모량·쿨타임·데미지 배율을 적용 전에
거부합니다. 같은 시트에 중복된 열 이름이 있으면 시트와 열 위치를 안내하고
데이터를 적용하지 않습니다. 일부 스킬 참조와 스킬 버프·투사체·애니메이션·사운드 및
레벨·경험치 및 몬스터 AI 패턴 설정의 구조도 검사합니다. 불완전한 AI 패턴은
이제 기본값으로 대체하지 않고 가져오기 오류로 표시합니다. AI 공격·스킬 패턴의
스킬 ID도 검사하되 기존 `skill1`~`skill4` 슬롯 표기는 허용합니다. 플레이어·몬스터
설정의 캐릭터 타입 참조와 캐릭터 능력치 수식 필드의 구조도 검사합니다. 슬롯 배치와
실제 실행 성공 및 다른 값과
참조의 검증은 아직 완성되지 않았습니다. 레벨 고급 공식 블록은 Excel에
보존되지만 현재 능력치 계산에는 연결되어 있지 않으며, 이전 Excel 파일에 빠진
블록은 복구할 수 없습니다. 경험치와 캐릭터 능력치 수식은 브라우저에서 코드로
실행되고 안전성이 검증되지 않으므로 신뢰할 수 없는 Excel 파일을 가져오지 마세요.
플레이어·몬스터 데이터 행의 HP와 SP는 빈 값 또는 0 이상의 유한한 숫자여야 하며,
숫자 문자열은 숫자로 변환합니다.
데이터 행의 기본 공격과 스킬 편집기에서는 사거리, 범위, 피해 배율, 쿨타임,
SP 소모와 시전시간을 0으로 설정할 수 있으며 저장된 0도 그대로 표시합니다.
기존 행에 잘못된 수치가 있으면 편집기에서 해당 필드를 안내하고 임시로 슬라이더를
0에 표시합니다. 원본은 그대로 유지되며, 사용자가 슬라이더나 `0으로 수정`을
선택해야 해당 값이 바뀝니다.
Excel의 해당 수치는 숫자 문자열을 변환하고 빈 값과 0을 보존하며, 숫자가 아니거나
유한하지 않으면 가져오기 전에 오류를 표시합니다. 음수의 허용 범위는 아직 정하지 않았습니다.
Excel 가져오기 직후 적용할 행의 크기·레벨·전투 설정 수치는 숫자 문자열을 변환하고,
잘못된 값은 적용 전에 거부합니다. 크기가 비어 있으면 그 행은 적용하지 않습니다.
선택되지 않은 레거시 행은 가져올 때 보존하고, 나중에 설정에 적용할 때 같은 필드를
검사합니다. 적용 시 숫자 문자열을 변환하되 원본 데이터 행은 변경하지 않습니다.
직접 행을 적용할 때는 실제 적용되는 기본 공격과 플레이어 스킬 수치도 검사합니다.
해당 스킬이 선택되지 않은 초안 수치는 그대로 보존합니다.
Excel의 캐릭터 설정에 포함된 선택 필드 `monsterRespawnDelay`와 `monsterMaxCount`도
빈 값과 0을 구분해 왕복합니다. 이는 별도의 시뮬레이터 전역 생성 설정과 구분됩니다.
플레이어 데이터셋에서 같은 캐릭터의 레벨별 행에는 같은 캐릭터 ID를 입력합니다.
Excel의 `player_character_id`와 `player_level` 조합은 중복될 수 없습니다.
ID가 없는 기존 행도 가져올 수 있지만, ID는 자동 생성되지 않습니다. 이 행들을
사용하면 기존 설정으로 시작하되 레벨업은 경고와 함께 보류됩니다. ID가 있는
행은 시작 시 현재 레벨에 해당하는 같은 ID의 행을 사용합니다. HP, SP, 공격력,
방어력, 속도, 공격속도, 명중, 크리티컬이 필요하며 HP는 양수, 나머지는 0 이상의
유한한 숫자여야 합니다. 시작 행이 없거나 불완전하면 시작이 차단됩니다.
레벨업에서는 다음 행이 없거나 중복·불완전하면 경험치를 보존하고 진행을
보류합니다. 여러 레벨을 한 번에 얻을 때는 첫 오류가 발생한 레벨에서 보류합니다.
캐릭터 ID가 있는 행은 레벨·크기나 성장 설정을 바꿔도 능력치를 재계산하지
않습니다. ID가 없는 레거시 행은 기존 재계산 동작을 유지합니다.
캐릭터 ID가 있는 행의 필수 능력치는 화면에서 직접 숫자로 입력할 수 있습니다.
빈 값도 저장할 수 있지만 필수 값이 빠진 행은 실행할 수 없습니다.
Excel의 해당 능력치 숫자 문자열은 숫자로 변환하고, 음수나 숫자가 아닌 값은
가져오기 전에 거부합니다. ID 없는 행의 기존 편집 방식은 유지됩니다.

캐릭터 타입 관리 화면에서는 플레이어·몬스터 설정, 몬스터 타입 정의 또는 데이터
행에서 사용 중인 타입을 삭제할 수 없습니다. 안내된 사용처에서 참조를 먼저 해제하세요.
스킬 화면에서도 캐릭터·몬스터 타입, 데이터 행 또는 AI 패턴이 참조하는 스킬은
삭제할 수 없습니다. AI의 기존 슬롯 표기 `skill1`~`skill4`는 스킬 ID 참조와 구분합니다.
현재 슬롯과 기본 공격에 내장된 스킬 객체는 이 삭제 검사에 포함되지 않습니다.
Excel 데이터 행의 타입 값이 있으면 캐릭터 타입 시트에 정의되어 있어야 합니다.
기존 파일의 공격 방식 값이 타입 ID가 아닌 경우 자동 변환하지 않고 오류를 표시합니다.
캐릭터 설정 시트가 비어 기존 설정을 유지하는 경우에도, 선택 행을 적용한 뒤 사용할
타입이 새 타입 목록에 없으면 기존 데이터를 바꾸기 전에 가져오기를 거부합니다.
Excel을 가져올 때 플레이어·몬스터 데이터 행의 값은 레벨 설정으로 재계산하지 않고
그대로 보존합니다. 이후 레벨 기본값이나 성장 설정이 바뀌면 몬스터 행과
ID가 없는 플레이어 행은 기존처럼 재계산됩니다.
가져온 선택 행의 값은 별도 캐릭터 설정보다 우선 적용됩니다. 선택 행이 양쪽에
모두 없으면 첫 행을 선택하며, 한쪽 행이 없거나 크기가 없으면 해당 설정은
적용하지 않고 경고합니다. 이전 1:다 몬스터 행 선택은 해제됩니다.
플레이어 행의 스킬 ID가 비어 있으면 해당 슬롯은 비워집니다. 레거시 파일에서
스킬 열이 누락된 경우도 마찬가지입니다. 플레이어 행의 공격·방어·이동 속도와
공격속도·명중·크리티컬 설정을 실행 상태에 반영하지만, 모든 피해·명중·
크리티컬 판정 경로가 이 값을 사용하는 것은 아닙니다. 실행 중 데이터 변경의
전체 스냅샷 정책은 미완료입니다.
몬스터 초기 생성과 개체 수 증가는 배치 생성기를, 리스폰은 같은 단일 생성기를
사용해 몬스터 구성을 일관되게 적용합니다.
초기 생성과 개체 수 조절은 설정된 최대 몬스터 수를 초과하지 않으며, 실행 중
최대 수를 낮추면 초과 개체를 제거합니다.
리스폰 시간은 프레임마다 한 번 감소하며, 리스폰 제한에 도달하면 자리가
생길 때까지 대기합니다. 생성 시 선택된 몬스터 행의 이름·색상·AI·스킬·
기본 공격과 HP·SP·공격력·방어력·이동 속도를 사용합니다. 해당 행의 HP, SP,
공격력, 방어력, 속도, 공격속도, 명중, 크리티컬은 모두 0보다 큰 유한한
숫자여야 하며, 누락되거나 0이면 시작·개체 추가·리스폰을 보류합니다.
실행 중 잘못된 행을 수정하면 보류된 리스폰을 다시 시도합니다.
기본 공격과 ID가 지정된 몬스터 스킬 수치도 생성 전에 확인합니다. 숫자 문자열은
실행용 복사본에서 변환하고 잘못된 값은 시작·추가·리스폰을 보류합니다.
비어 있는 수치는 기존 기본값을 사용하며 원본 데이터는 변경하지 않습니다.
선택된 몬스터 행의 가중치 기반 생성에서는 가중치 0을 생성 제외로 처리하고,
빈 값은 1로 취급합니다. 숫자 문자열을 허용하며 음수·유한하지 않은 값 등은
오류입니다. 선택된 가중치가 모두 0이거나 잘못되면 시작·추가·리스폰을 보류합니다.
제외된 0 가중치 행의 미완성 전투 수치는 다른 후보의 생성을 막지 않습니다.
이 규칙은 가중치 선택에만 적용되며, 스테이지·웨이브의 ID와 수량에 의한 명시적
생성 및 선택 행이 없을 때 현재 행의 직접 생성에는 적용되지 않습니다.
Excel 가져오기는 빈 값과 0을 구분하고 잘못된 가중치가 있으면 일부도 적용하지 않습니다.
몬스터 데이터셋에서 해당 능력치를 직접 숫자로 입력할 수 있으며, 빈 값이나
0 이하의 값은 적용되지 않습니다.
Excel의 몬스터 능력치 숫자 문자열은 숫자로 변환하고 음수나 숫자가 아닌 값은
거부합니다. 빈 값과 0은 편집용으로 가져올 수 있지만 시뮬레이션에서는 사용할
수 없습니다. 데이터셋은 버전이 지정된 사용자 작업공간 스냅샷으로 SQLite에 저장됩니다.
공격속도·명중·크리티컬의 모든 판정 적용과 몬스터 스킬 SP 소모는 미완료입니다.
몬스터의 레벨·크기·성장 설정을 바꾸면 능력치 행이 재계산될 수 있습니다.
플레이어 레거시 행이나 몬스터 행의 레벨·크기가 잘못된 경우 자동 재계산은 해당
행을 건너뛰고 안내합니다. 직접 수정 중 다른 값이 잘못되면 그 값이 수정될 때까지
기존 능력치를 보존합니다.
주 시뮬레이터의 아이템·기본 공격·투사체·스킬 처치는 공통 사망 처리를 사용해
HP를 0으로 정리하고 처치 수와 경험치를 개체의 사망당 한 번 반영합니다.
리스폰을 끄면 사망 개체를 제거하고, 즉시 리스폰도 비활성 설정을 따릅니다.
스테이지·웨이브는 몬스터 행 ID와 수량을 매핑해 실행합니다. 웨이브 시간이 끝나면
남은 몬스터를 제거하고 다음 웨이브로 진행하며, 마지막 웨이브 뒤에는 스테이지를
완료합니다. 웨이브 전환 시 생존 몬스터를 유지할지 여부는 임시 정책으로, 후속 기획
확인이 필요합니다.
Excel 웨이브 매핑에는 스테이지 ID와 웨이브 ID가 함께 저장됩니다. 스테이지 ID가
없는 이전 파일은 웨이브 ID가 파일 전체에서 고유하면 그대로 가져옵니다. 같은
웨이브 ID가 여러 스테이지에 있으면 각 매핑에 스테이지 ID를 입력해야 합니다.
같은 웨이브 ID를 여러 스테이지에서 사용하는 새 파일은 이전 프로그램에서
가져오지 못할 수 있습니다.
이름이 비었거나 웨이브·몬스터 매핑이 없고 지속 시간·수량이 0인 초안도 Excel로
보존합니다. 단, 실행하려면 이름과 웨이브·매핑을 채우고 시간·수량을 양수로
수정해야 합니다. 수량 0인 매핑도 몬스터 참조로 취급합니다.
사용자 정의 공격 스킬의 피해 판정과 실행 중 설정 스냅샷은 아직 완성되지 않았습니다.
